### Document runtime and deployment

The release pins Node.js 24 in `package.json` and `.nvmrc`, overriding the discontinued Node 20 project setting. Next.js 15.5.28 includes the current patched 15.x release; dynamic route parameters use its asynchronous API. The original approved layout, copy and motion remain. The shared YL monogram appears in the header, SVG/favicon and Apple home-screen icon.

On Vercel, `api/extract_document.py` is a native Python function using pinned PyMuPDF/Pillow dependencies and bundled Apache-2.0 English OCR data under `data/ocr/`. Locally the Next handler runs the same extraction core through `/usr/bin/python3`. The build selects the endpoint; no external OCR/AI provider receives documents and no worker credential is required. PDF/image limits are 3.5 MB, 2 pages and bounded dimensions, with a 30-second production function limit. Compact source previews keep JSON below the hosting response limit. The worker uses no persistent upload files.

The function validates multipart uploads and same-origin browser calls, isolates one active extraction per process, prefers the PDF text layer and otherwise runs local OCR. Explicit delivery/dispatch label rules detect fields; arbitrary document understanding is not claimed. All seven fields require review before export. The original synthetic files under `public/samples/` are generated by `scripts/create-document-samples.py`.

### Revenue workflow

Select an opportunity, configure its scope and discount, review policy exceptions, then advance it through qualification, proposal, and won. Discounts above 10% or margins below 25% require simulated approval. Quote edits clear approval; editing a proposal returns it to qualification. Won quotes are locked. Adding the same sample enquiry twice is blocked by an email duplicate check.

The forecast separates won business from open pipeline. Open stage weights are New 15%, Qualified 40%, Proposal 70%. Quote calculations use integer cents. An empty quote cannot advance to proposal.

### Purchasing workflow

The five-record sample includes a clean invoice, a partial delivery, a price discrepancy, and two copies of one supplier invoice. Record the missing delivery, adjust price tolerance, or resolve the duplicate to see the approval gate respond. Quantity checks consider all invoices for the same order/item in the current batch, preventing split invoices from bypassing the check. Duplicate supplier numbers are compared without case or surrounding whitespace.

Changes to invoice data, delivery evidence, or matching rules invalidate all session approvals conservatively. The activity log records changes and simulated approvals. This prototype does not reconcile against historical paid invoices, persist an audit log, or enforce real user roles.
